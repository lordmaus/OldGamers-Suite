# TimerStudio Code Audit — 2026-05-11

27 findings across 4 severity levels.

---

## CRITICAL (4)

### C-1 · MediaPlayer STA thread never shut down — thread + COM leak per alert
**File:** `Core/AlertSoundPlayer.cs` lines 40–65  
`Dispatcher.Run()` starts an infinite message loop on the STA thread. `MediaPlayer` has no way to signal completion and call `Dispatcher.InvokeShutdown()`. Each custom-sound play leaks one STA thread and one MediaPlayer COM wrapper. With 4 alert repeats = 4 leaked threads per alert event.  
**Fix:** Hook `MediaPlayer.MediaEnded` → call `Dispatcher.CurrentDispatcher.InvokeShutdown()` then `player.Close()` before shutdown.

---

### C-2 · Double-dismiss race with AlertStyle.Both — Pomodoro/recurrence advances twice
**File:** `ViewModels/TimerCardViewModel.cs` lines 749–772  
Both `_flashOverlay` and `_lensAlert` each fire `Dismissed` → `DoDismiss()`. The guard `if (!AlertActive && AlertDismissed)` only kicks in after the first call has already mutated state. The second call passes the guard and re-advances the Pomodoro phase or recurrence.  
**Fix:** Set `_model.AlertActive = false` as the very first statement in `DoDismiss()` before any state mutation.

---

### C-3 · `_calendarPollTick` not stopped in `OnClosed` — fires on destroyed window
**File:** `MainWindow.xaml.cs` line 1830 (OnClosed)  
`_tick` and `_saveTick` are stopped, but `_calendarPollTick` is not. After the window closes, the poll fires, accesses `TimerPanel.Children`, and calls `Dispatcher.InvokeAsync()` on a disposed dispatcher → `ObjectDisposedException`.  
**Fix:** Add `_calendarPollTick?.Stop();` to `OnClosed` alongside the other timer stops.

---

### C-4 · `TimerHistory.Record` fragile null-coalesce — potential NullReferenceException on future refactor
**File:** `Core/TimerHistory.cs` lines 52–53  
`(notes ?? "").Length > 200 ? notes.Substring(0, 200) : (notes ?? "")` — the length check runs on the coalesced value but the `.Substring()` branch operates on the original `notes` variable. Currently safe because null → 0 length, but a future refactor exposes a null dereference.  
**Fix:** `notes = notes?.Length > 200 ? notes[..200] : (notes ?? "");` before constructing the entry.

---

## HIGH (6)

### H-1 · `TimerModel._nextId` non-atomic — duplicate IDs under concurrent construction
**File:** `Core/TimerModel.cs` lines 22, 107  
`_nextId++` is a plain int increment. Concurrent construction (calendar poll + main thread) can produce two timers with the same ID, breaking dedup, overlay keying, and history.  
**Fix:** `Interlocked.Increment(ref _nextId)` everywhere `_nextId` is mutated.

---

### H-2 · `RunCalendarPoll` — `AppPrefs.HiddenCalendarPaths` read concurrently from background Task
**File:** `MainWindow.xaml.cs` lines 988–1051  
`hidden` list is built from `AppPrefs.HiddenCalendarPaths` on the UI thread, then a `Task.Run` closure reads it while the UI thread may modify it. `List<string>` is not thread-safe.  
**Fix:** `var hidden = new List<string>(AppPrefs.Instance.HiddenCalendarPaths);` — defensive copy before entering `Task.Run`.

---

### H-3 · `AlertSoundPlayer.PlayCustom` blocks a thread-pool thread for up to 10 s via `thread.Join`
**File:** `Core/AlertSoundPlayer.cs` lines 35–72  
`Task.Run` wraps a `thread.Join(10 s)` call. Under concurrent alerts, thread-pool starvation causes UI lag and delayed ticks across all running timers.  
**Fix:** Remove the outer `Task.Run`; call the STA-thread creation and join directly. The STA thread (`IsBackground = true`) handles the background execution.

---

### H-4 · SMTP password AES key derived from `UserName + MachineName` — trivially reproducible
**File:** `Core/EmailAlertService.cs` lines 26–31  
Any process running as the same user can derive the identical key. The password is effectively plaintext-equivalent. DPAPI is already used for the OAuth cache.  
**Fix:** Replace `GetKey()`/AES with `ProtectedData.Protect/Unprotect(DataProtectionScope.CurrentUser)`.

---

### H-5 · Pomodoro resume restores wrong `StartedAt` — timer restarts from full duration
**File:** `ViewModels/TimerCardViewModel.cs` lines 720–734  
Pomodoro falls through to the Stopwatch `else` branch in `DoResume()`. `PausedElapsed` is zero for Pomodoro, so after resume the timer shows the full duration instead of remaining time.  
**Fix:** Add an explicit Pomodoro branch: `_model.StartedAt = DateTime.UtcNow - (_model.TotalDuration - _model.PausedRemaining);`

---

### H-6 · `IcsUrlFetcher` no response size limit — large feeds exhaust memory / disk
**File:** `Core/IcsUrlFetcher.cs` lines 43–52  
`GetStringAsync(url)` loads the full response with no `MaxResponseContentBufferSize`. A 500 MB feed allocates ~1 GB in-memory (UTF-16) and writes 500 MB to temp dir.  
**Fix:** `_http.MaxResponseContentBufferSize = 10 * 1024 * 1024;` and stream-read, rejecting responses exceeding the limit.

---

## MEDIUM (9)

### M-1 · Active chip uses same background as inactive — WCAG 1.4.1 (Use of Color) violation
**File:** `MainWindow.xaml.cs` line 1722  
Both active and inactive filter chips use `inactiveFill` for background. Only border colour distinguishes them — colour-only information.  
**Fix:** Use `active ? FindResource("BrushBlue") as Brush : inactiveFill` for the active fill, or add a visible glyph (checkmark).

---

### M-2 · `LensPopupBase._stackCount` grows unboundedly — late alerts position off-screen
**File:** `Windows/LensPopupBase.cs` lines 18, 38–42  
`_stackIndex` is assigned from an ever-increasing counter, not from the current live count. After many alert cycles the offset is hundreds of pixels — off-screen on low-res displays.  
**Fix:** Assign `_stackIndex` as the current live count snapshot after increment, which is what the paired decrement-on-close correctly tracks.

---

### M-3 · Magic constant `7` (built-in preset count) with no named reference
**File:** `Windows/TimerCard.xaml.cs` lines 389–390, 218  
If a built-in preset is added/removed, the hardcoded `7` silently misfires — user templates get treated as built-ins.  
**Fix:** `private const int BuiltInPresetCount = 7;` referenced in both places.

---

### M-4 · `TimerModel.Name` and `Notes` have no length cap — unbounded prefs.json growth
**File:** `Core/TimerModel.cs` lines 25, 63; `MainWindow.xaml.cs` line 576  
Pasting large text into Name or Notes persists on every 30 s autosave tick.  
**Fix:** Clamp Name ≤ 255 chars and Notes ≤ 10 000 chars in ViewModel property setters.

---

### M-5 · `FlashOverlayWindow.DoDismiss()` fires `Dismissed` before `Close()` — if Close throws, fullscreen alert stays open forever
**File:** `Windows/FlashOverlayWindow.cs` lines 176–182  
Fix: Call `Close()` first (in try/catch), then fire `Dismissed`.

---

### M-6 · `OverlayWindow.OnClosing` cancels all closes unconditionally — can block `Application.Shutdown()`
**File:** `Windows/OverlayWindow.xaml.cs` lines 103–107  
Fix: Check a `_reallyClosing` flag (as `MainWindow` does) and skip cancellation during genuine shutdown.

---

### M-7 · `AppPrefs.Save()` called synchronously on UI thread in every slider `ValueChanged` — blocks UI on rapid drag
**File:** `Windows/AppSettingsDialog.xaml.cs` lines 55–91 and many MainWindow callers  
Fix: Debounce with a 500 ms `DispatcherTimer`; only call `Save()` after the last change settles.

---

### M-8 · Snooze converts Pomodoro to Countdown permanently — loses session count and phase
**File:** `ViewModels/TimerCardViewModel.cs` lines 782–796  
Fix: Add an explicit Pomodoro snooze branch that restores `TimerMode.Pomodoro` after the snooze period.

---

### M-9 · `DiagLog` logs email `to=` address in production — low-severity PII leak to log file
**File:** `Core/EmailAlertService.cs` line 222  
Fix: Replace `"to=" + to` with `"to=<redacted>"` in non-debug builds. Also verify DiagLog rotates at ≤1 MB.

---
